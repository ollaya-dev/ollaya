# Ollama 0.40.6 against Ollaya, October 2026

Ollama 0.40 (October 2026) serves nine decision models through TypeSafe's `/v1/systemone`, up from two in 0.35.
This note measures all of them on the suites of Ollaya Bench 2026.10, on the same machine as that edition, and lists
what Ollaya took from Ollama's code.

## Setup

- **Machine.** hope: Threadripper 3960X, RTX 5090 (32 GB), WSL2 Ubuntu 24.04. The Ollaya rows are Ollaya Bench
  2026.10 (`results/runs/2026-10-14-*`, Ollaya 0.13.0) on the same machine, except the rows marked *branch*: the models this branch adds, measured the same way on 2026-10-18 with Ollaya
  0.13.0 built from the branch.
- **Ollama.** 0.40.6 (`ollama-linux-amd64`, 2026-10-16), one model loaded, one request at a time
  (`OLLAMA_NUM_PARALLEL=1`), each tag as `ollama pull` serves it (sizes below).
- **Suites.** Bespoke Labs' public suite (3,880 human-labeled questions from 13 datasets, scored with Bespoke's code;
  `ollaya_convert.bench_public`) and the typed-decisions test split (400 requests, 2,000 questions;
  `ollaya_convert.bench_typed`). Latency is the client's median per question (public) or per five-question request
  (typed), over HTTP.
- **Scripts.** `o2610/run.sh` and `run-extra.sh` on hope, `ollaya_convert.bench_* run --url --model`, then
  `bench_* report`.

## Findings

1. **Speed.** On the same checkpoints and GPU, Ollama answers 4 to 8 times faster on the public suite (Nimble 42 ms
   against 328, Kev 4B 34 against 187, Clef-Flash 43 against 284) and 3 to 21 times faster per typed request
   (Kev 0.8B 99 ms against 300, Nimble 141 against 2,990). Ollama runs Q8_0 GGUFs on llama.cpp; Ollaya computes in fp32 on the authors' BF16
   weights. Ollaya's own llama.cpp families (`jeb`, `snap`, `d1`) are as fast as Ollama's.
2. **Accuracy.** Equal within a point where both serve the same checkpoint: Q8_0 costs nothing measurable here
   (Nimble 0.752 against 0.748, Kev 4B 0.744 against 0.745, Kev 0.8B 0.612 against 0.611, Clef-Flash 0.772 both).
3. **Calibration.** Ollaya is better where an author fitted a temperature: Nimble's pooled ECE is 0.022 in Ollaya
   against 0.115 in Ollama, which reads Nimble's softmax at temperature 1 (`decision/` applies no temperature). Where
   the model needs none (Clef), both match.
4. **Models.** Ollama had four models Ollaya did not: Perplexity's pplx-decider, Bespoke Labs' Nimble v3, Strands
   Decider and Together AI's Tev1. This branch adds pplx-decider's open flash model (`pplx-decider:flash`; the 27B
   needs about 54 GB in Ollaya's runtime), Nimble v3 (`nimble:9b-v3`) and Strands Decider (`strands-decider:2b`).
   Tev1's weights have no published license, so Ollaya does not serve them.
5. **The strongest models are Perplexity's.** Ollama's pplx-decider (27B v1.1 at Q4_K_M) leads Ollama's models
   (0.816, pooled ECE 0.017). Ollaya's port of the 4B flash model scores higher on both suites (0.824, ECE 0.016;
   typed 0.726 against 0.702), at 232 ms against 96 per question. Ollaya's best before it was `jeb:27b` (0.788).
   Running the 27B in Ollaya needs the reduced-precision path below.
6. **Nimble v3 is no better than v2 here** (0.754 against 0.748 public, 0.647 against 0.665 typed) and is worse
   calibrated: the author ships no temperature for it.

## What Ollaya takes from Ollama's code

Read at Ollama `2476d5ea` (v0.40.6). Each item is in `docs/backlog.md`:

- **A reduced-precision path for the Qwen3.5 families** (findings 1 and 5). Ollama quantizes at `ollama create`
  (`create/create.go`) and hands decision requests to llama.cpp's decision server (`llm/llama_server.go`,
  `server/routes.go`), whose build knows the kev, nimble, clef, laya and pplx-decider decision types natively.
- **Questions from the command line** (`cmd/decide.go`: `--ask`, `--choice label[=description]`, `--level`).
- **A decision integration corpus** run against every release (`integration/systemone_test.go`).

Ollaya keeps what Ollama does not do: the authors' temperatures, parity gates against each author's own code,
TypeSafe's limits (256 questions, 255 options) wherever a model allows them, and weights downloaded from the authors' repositories
rather than re-hosted.
